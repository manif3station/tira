# DD-413

## Title

Drops onto populated columns bounce back: resolve the drop target to the
whole column stripe.

## Method

Browser BDD under the Mandatory Problem-Solving Loop.

## Problem-Solving Loop record

1. **Expected:** releasing a dragged card anywhere over a column — on,
   between, or below its existing cards — moves the card there.
2. **Problem:** owner report (messages 2880/2881): dropping onto a column
   that already holds a card bounces back.
3. **Root cause:** the drop target required the release point to be inside
   the `.cards` list, which only spans its content height. On a populated
   column the natural release point (below the existing cards) lands
   outside the list — reproduction showed `MAIN.shell` under the pointer
   and zero `/move` requests. Empty columns worked because their compact
   list sits exactly where users aim, which is also why every prior drag
   test (all empty-column targets) missed this.
4. **Reproduction:** fixture with a resident card in the target column;
   release 45px below it; pre-fix: 0 moves.
5. **Pre-fix comparison:** onto-card and empty-column drops post `/move`;
   the below-card release posts nothing — mismatch confirmed.
6. **Fix:** geometric drop resolution scoped to the card's own board:
   direct list hits win; otherwise the column whose horizontal band
   contains the pointer, within the board's vertical stripe; outside the
   board cancels. Cross-board drops structurally excluded.
7. **Re-run:** the identical release posts exactly one `/move` with the
   right column; all previous drop styles still pass on desktop and touch.
8. **Guard:** the permanent desktop scenario now releases into the former
   dead zone against a populated column; the mobile scenario drops onto
   the populated column.
