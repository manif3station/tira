# DD-466

## Title

The column editor.

## Epic

EPIC-457 — settled point 15, the UI half.

## Owner decision this implements

Point 15, in his words: a button on each board control opening a modal
shaped like the card modal, but showing the board's structure rather
than a card's. Add a column, remove one, drag them into a different
order — "like an iPhone, a three-line icon you hold and pull up and
down" — and set each column's notification time. Plus point 7's eye,
which decides whether a column is chased at all.

## Design

- One button per board control, because each board has its own columns.
- The dialog is built from `/columns` when it opens, so it always shows
  what is stored rather than what the page happened to be rendered
  with.
- Reordering is **pointer-based, not HTML5 drag**. The board replaced
  HTML5 drag with pointer events so cards can be dragged on a phone,
  and a test guards that. The grip he asked for has to work the same
  way or it would be the one thing on the board that a phone cannot
  move.
- Protected columns have no remove control at all, rather than an
  enabled one that fails: the engine refuses them, and offering a
  button that always errors is worse than not offering it.
- A new column is inserted before Discard, which is where it belongs
  and where `column_add` already puts one.
- Save sends the whole layout to `column_apply`, which works out the
  difference. The dialog never has to know what changed.
- An empty threshold is **omitted** rather than sent as zero, so
  clearing a column's own limit falls it back to the project default
  instead of being refused as an invalid number.

## Acceptance criteria

1. Each board control offers the editor and it opens showing that
   board's columns.
2. Stored thresholds and watched flags are shown as they are stored.
3. A protected column offers no remove control.
4. A row can be dragged by its grip into a new position.
5. A new column is added before Discard and refuses a name with no
   letters or digits, or one already on the board.
6. Saving sends exactly what is on screen, with an untouched threshold
   omitted rather than sent as a value.

## Verification note

Browser-gated with `t/playwright/column-editor.js`, driven with real
pointer events. The guard was itself checked in the failing direction
against three deliberately broken builds — no button, a dead grip, and
a dropped threshold — because a guard that cannot fail proves nothing.
