# DD-491

## Title

Every response tells the agent what it still owes.

## Source

Owner, message 3209: if a question has no voice note, the response
should say so and name the command that adds one — "like an
advertisement", his words, because an agent will not use a feature it
is never told about. And if the question's wording, reason or choices
change, the response should point out that the recording no longer
matches, unless the same action already replaced it.

His general principle, stated in the same message: every action's
response carries its reminders, so nothing is missed and every agent
behaves the same way without having to remember the rules.

## Corrected by the owner (message 3214)

My first version wrote prose: full sentences explaining what was
missing and why it mattered. He pointed out the mistake, and it is a
real one — **these lines are read by an LLM, not by a person**, and
Tira exists to spend fewer tokens than Jira. Prose written for a human
reader is precisely the cost the tool is meant to avoid.

Rewritten as one terse machine line: what is missing, then the commands
that fix it joined by semicolons, references already filled in. Two
gaps that share a command get one command rather than two.

    missing: reason,options,voice | fix: tira.question.update --id Q-007 --reason TEXT --option TEXT --option TEXT; tira.question.voice --id Q-007 --file FILE

## Design

A `reminder` on the question itself, derived rather than stored, so it
cannot fall out of step with the facts:

- **No recording** → name the command that adds one.
- **A recording older than the last change to the question** → say the
  recording describes an older version and name the command that
  replaces it.
- **Neither** → no reminder at all. A reminder that is always there is
  furniture, and gets ignored like furniture.

For the second rule the question needs to know when it last changed, so
`question.update` now stamps that. A recording attached afterwards is
newer than the change; one attached before is stale by definition.
Nothing to keep in step by hand.

## Why derived, and why on the question

Putting it on the question rather than only in the list means every
command that returns a question carries it — asking, updating, marking
— so the agent is told at the moment it acts rather than only when it
happens to list.

## Acceptance criteria

1. A question with no recording carries a reminder naming the command.
2. Changing the wording, the reason or the choices makes an existing
   recording stale, and says so.
3. Replacing the recording clears it.
4. Attaching a recording in the same breath as the change leaves no
   reminder.
5. A question that owes nothing carries no reminder.
6. It appears wherever a question is returned, not only in the list.
7. Documented in both manuals.
