# DD-410

## Title

Make card drag-and-drop work on touch devices by replacing HTML5 DnD with a
Pointer Events engine.

## Method

Browser BDD (Playwright, desktop + touch) under the Mandatory
Problem-Solving Loop.

## Problem-Solving Loop record

1. **Expected happy path:** dragging a card to another column posts `/move`
   (physically moving the record's JSON file) and refreshes placement —
   with a mouse on desktop AND with a finger on a phone; a plain tap still
   opens the card dialog.
2. **Problem:** the owner reports drag does nothing on mobile (Telegram
   message 2859) and asks for a desktop check.
3. **Root cause:** the board uses HTML5 drag events (`dragstart`,
   `dragover`, `drop`) with `draggable=true`. Mobile browsers do not
   synthesize HTML5 DnD events from touch gestures at all, so no drag can
   ever begin on a phone. Desktop works, but intermittent gate flakes
   suggest the same engine is marginal there too.
4. **Reproduction:** a Playwright touch context (430x932, `hasTouch`)
   performing a touchscreen press-move-release across columns; observed
   result pre-fix: zero `/move` requests.
5. **Pre-fix comparison:** desktop `dragTo` posts `/move`; the touch
   reproduction posts nothing — mismatch confirmed.
6. **Fix:** one Pointer Events code path for mouse and touch: pointer down
   arms a drag (movement threshold for mouse, ~250ms hold for touch so
   page scrolling still works), a floating ghost follows the pointer, the
   column under the pointer highlights via `elementFromPoint`, and release
   over a column list posts the same `/move` payload. A sub-threshold
   press stays a click and opens the dialog.
7. **Re-run:** the same touch reproduction posts `/move` with the right
   payload; desktop drag still posts `/move`; tap opens the dialog.
8. **Guard:** the Playwright suite gains a touch-drag scenario in the
   mobile pass and keeps the desktop drag scenario; the renderer contract
   test pins the pointer-event engine.

## Acceptance

- touch drag on a 430px `hasTouch` context posts `/move` with the correct
  ref and column and refreshes placement
- desktop mouse drag still posts `/move`; a plain click/tap (below the
  drag threshold) still opens the card dialog
- normal touch scrolling is not hijacked: a quick swipe on a card scrolls
  without starting a drag (hold-to-drag)
- the HTML5 DnD path is fully replaced — one engine for both inputs
- Docker tests pass; coverage `100.0%` statement and subroutine; taint and
  primitive-scan gates pass; `cover_db` cleaned
- Playwright desktop and mobile passes green; visual review of the drag
  ghost and column highlight
- `README.md`, `docs/`, `SKILLS.md`, `Changes`, `VERSION 0.21`, tickets,
  commit, and push complete from the `tira` repository
