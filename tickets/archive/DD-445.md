# DD-445

## Title

Column dropdown labels included the card count.

## Method

Browser BDD (Playwright, red-first) under the Mandatory Problem-Solving
Loop.

## Problem-Solving Loop record

1. **Expected:** each option in the card dialog's column dropdown reads
   the column's name and nothing else.
2. **Problem:** owner photo (message 2990) shows `backlog46`,
   `in-review1`, `done64`.
3. **Root cause:** DD-422 built each option's label from the header
   cell's `textContent`. DD-441 then placed the count badge inside that
   same header cell, so the badge's digits were concatenated into every
   label. The option *values* come from the list's `data-column`, which
   stayed clean — so moving a card always worked and only the visible
   text was wrong.
4. **Reproduction:** assert the dropdown's visible labels in the
   existing Playwright dialog scenario.
5. **Pre-fix comparison:** failed with `["backlog2","in-progress1"]` —
   the reported defect, at fixture scale.
6. **Fix:** read the `.column__name` element inside the header, falling
   back to the header text and then to the column slug, so the label is
   the column's own name regardless of what else the header carries.
7. **Re-run:** labels are `backlog` and `in-progress`; Playwright ×3.
8. **Guard:** the dialog scenario now asserts the visible labels — that
   no label contains a digit, and that each label pairs with its own
   value — because the previous guard checked values only, which is
   exactly why it passed while the UI was visibly wrong. The renderer
   contract also pins the `.column__name` lookup.
