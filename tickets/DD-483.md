# DD-483

## Title

Every question command and argument, documented to 100%.

## Source

Owner, live, emphatically: "every piece of detail how to use the
question and answer in command and argument, needs to be documented
comprehensively in commands.md and skills.md. make sure 100% cover".

## Why this is its own ticket

The question surface grew across five releases — ask, list, answer,
update, mark, discard, plus reason, options, status filtering, time
filtering and decomposition. Each release documented what it added.
Nothing has checked that the *whole* surface is covered, and a manual
that is 90% complete is one an agent cannot trust, because it cannot
tell which 10% is missing.

## What "100%" has to mean here

Not "I read it and it looks complete". Every command that exists and
every option that reaches it, enumerated from the code and checked
against both manuals **by a test**, so the docs cannot drift again
silently.

## The surface, from the dispatcher

Six commands: `ask`, `list`, `answer`, `update`, `mark`, `discard`.

Options that reach them: `--ref`, `--id`, `--text`, `--reason`,
`--option`, `--mark`, `--author`, `--status`, `--since`, plus `-o` on
every one.

## Acceptance criteria

1. `docs/commands.md` documents all six commands, every argument each
   accepts, whether it is required, and what it is for.
2. `SKILLS.md` covers the workflows: asking with context, reading and
   marking, catching up, decomposing, answering from the board.
3. A test enumerates the commands and options **from the code** and
   fails if either manual omits one.
4. That test fails if a new command or option is added without
   documentation.
