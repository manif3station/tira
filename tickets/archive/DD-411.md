# DD-411

## Title

Attachment timestamps with newest-first sorting, a collapsed top rich-text
comment composer, and newest-first comments.

## Method

Engine TDD + Browser BDD (Playwright)

## Problem

Owner instructions (Telegram message 2862): attachment chips need a
visible added-time and newest-first order; the comment composer should sit
above all comments, collapsed by default to save space, expand on tap, and
support basic rich text stored as markdown and rendered nicely; comments
should list newest first.

## Acceptance

- attachment references gain an `added_at` timestamp at add time (content
  and file paths alike); deduplicated re-adds retain the original
  timestamp; legacy references without one render an em-dash and sort last
- the dialog strip shows each chip's date and orders chips newest first;
  comment-owned chips sort the same way
- comments render newest first
- the composer renders above all comments as a single collapsed control
  that expands on click into author picker, formatting bar (bold, italic,
  code, bullet list), and textarea; posts store markdown text unchanged
- markdown comment bodies render formatted (bold, italic, inline code,
  bullet lists, paragraphs) through a DOM-building renderer that never
  injects raw HTML, so nothing can execute; `format: text` bodies stay
  plain
- Docker tests pass; coverage `100.0%` statement and subroutine; taint and
  primitive-scan gates pass; `cover_db` cleaned
- Playwright proves: chip order and visible timestamp, comment order, the
  collapsed-then-expanded composer, toolbar-inserted markdown reaching the
  `/comment/add` payload unchanged, and a `<strong>` element rendered from
  a bold comment with no raw HTML injection
- docs, `Changes`, `VERSION 0.22`, tickets, commit, and push complete

## Status

Done
