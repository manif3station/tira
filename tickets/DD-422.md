# DD-422

## Title

Column dropdown in the card dialog header for Jira-style moves from the
open card.

## Method

Renderer-contract TDD + Browser BDD (Playwright), with the Mandatory
Problem-Solving Loop applied to the regression the feature introduced.

## Problem

Owner instruction (Telegram message 2924, annotated screenshot): "Add a
drop down for the user to move the card to different columns in model
like jira."

## Design

- The dialog header ref line gains a `card-status` select beside the
  `REF · type` text, listing the type's columns read from the live board
  DOM (list `data-column` plus header labels), preselected to the card's
  current column.
- Choosing a column posts the same transactional `/move` payload as
  drag-and-drop, bumps the mutation seq, refreshes the board, and reloads
  the dialog in place — no bespoke move path.

## Problem-Solving Loop record (regression caught by the gate)

1. **Expected:** with the dialog open and no active editing, live refresh
   still updates dialog content (DD-420 behavior).
2. **Problem:** the mobile Playwright pass timed out waiting for the
   "Edited elsewhere" refresh after the dropdown was added.
3. **Root cause:** `showModal()` focuses the first focusable element —
   now the new select — and `dialogEditingActive()` treats any focused
   SELECT inside the dialog as active editing, permanently suppressing
   refresh.
4. **Reproduction:** the existing mobile guard itself (instrumented run
   showed refresh cycles firing but the reload gated off).
5. **Pre-fix comparison:** desktop pass green, mobile refresh wait red.
6. **Fix:** the close button carries `autofocus` so initial focus lands
   on a non-editing control; focusing the select deliberately (to pick a
   column) still suppresses refresh, which is correct.
7. **Re-run:** Playwright ×3 green including the mobile refresh wait.
8. **Guard:** the existing mobile refresh scenario now doubles as the
   regression guard; the desktop pass asserts the dropdown itself.
