# DD-482

## Title

Version 2: let an agent take a crammed question apart.

## Source

Owner, live: "in the version1 of the q&a the agent has not much room to
fit the choices and reason and everything squeezed into the question
field. for version2, we also consider, agent can revisit the questions
they created and update the question and decompose the choices and
reason from it and update the question in 3 pieces, either all done in
1 command or 3 different commands."

## The problem this solves

Every question asked before `--reason` and `--option` existed has all
three things crammed into its text, because that was the only field
there was. Those questions do not become readable on their own — an
agent has to be able to go back and split them apart.

This is a migration path, not a new feature: the questions that most
need choices and a reason are precisely the ones asked before either
existed.

## Design

`question.update` takes `--text`, `--reason` and `--option`, in any
combination:

- all three at once, for an agent tidying a question in one go;
- one at a time, for an agent that works out the pieces separately.

**Only what is named changes.** Passing `--reason` alone must not wipe
the options, and passing `--text` alone must not wipe either. That is
the difference between decomposing a question and rewriting it.

Clearing needs to be possible too, since an agent may decide a reason
it added is wrong: an explicitly empty value clears that piece, which
is the same rule `project.update` already uses for its settings.

## Acceptance criteria

1. `question.update` accepts text, reason and options together.
2. And each of them alone, leaving the others untouched.
3. An explicitly empty reason clears it; empty options clear them.
4. A question asked before this release can be decomposed into three
   pieces without being re-asked, keeping its reference and its stamp.
5. Both manuals document it.
