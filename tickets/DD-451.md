# DD-451

## Title

Board columns collapsed and cards spilled into the next column.

## Method

Browser BDD (Playwright) under the Mandatory Problem-Solving Loop, with
a new nine-column fixture because the existing two-column one could not
express the defect.

## Problem-Solving Loop record

1. **Expected:** in Standard width mode every column is a fixed 17rem
   and the board scrolls sideways; cards sit inside their own column.
2. **Problem:** owner photo (message 3005) on the MT5 board — cards
   visibly overlapping the neighbouring column, headers narrower than
   the cards beneath them.
3. **Root cause:** the board table is `table-layout: fixed`, and that
   algorithm takes every column's width from the **first row alone**.
   The header cells carried `min-width: 17rem` but no `width`, and a
   `min-width` on a header is not part of that computation, while the
   body cells' widths are never consulted at all. With few columns the
   table's `min-width: max-content` hid it; with nine columns the
   browser simply divided the available width — 134px each — and the
   cards, which cannot shrink below their content, spilled over.
4. **Reproduction:** a nine-column board at 1280px, measuring header
   widths and how far each card's right edge passes its cell's.
5. **Pre-fix comparison:** columns measured `[134 × 9]` against an
   expected 272; reverting the fix reproduces it exactly.
6. **Fix:** the header cells carry `width: 17rem` so the fixed layout
   honours the intended column size and the board scrolls, which is what
   Standard mode has always claimed to do. Fit mode still overrides both
   width and min-width, so it is unaffected.
7. **Re-run:** columns measure 272 in Standard and 122 in Fit, with no
   card spilling in either.
8. **Guard:** `t/playwright/wide-board.js` — a nine-column board
   asserting Standard keeps full-width columns with no spill, and Fit
   compresses without sideways scrolling. It fails on the pre-fix code.

## Why the existing guard missed it

The main browser fixture has two columns. At two columns the table is
narrower than the viewport whether or not the widths are honoured, so
the defect is invisible there. The lesson is in the fixture, not the
assertion: a layout rule that only bites at scale needs a fixture at
scale.
