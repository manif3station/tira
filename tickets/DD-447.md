# DD-447

## Title

Creating a project inside another one.

## Source

Found by the adversarial review of DD-446, recorded rather than changed
there because it was pre-existing and identical in both creation
commands.

## The defect

Without `--dir`, creation happens in the current directory. If that
directory sits anywhere inside an existing project's tree, the new
project is created inside the old one — and `discover_project` walks
upward, so from most places the wrong project answers.

The failure is quiet and it is durable. Cards go into a project the
person did not mean to create, in a directory they will not think to
look in, and every later command may address either one depending on
where it is run from. Nobody gets an error at any point.

## Fix

Creation refuses when an ancestor directory is already a project,
naming the project it found and where it is, so the message says what
happened rather than just refusing. `--nested` allows it for anyone who
genuinely wants it: the hazard is doing this by accident, not doing it
at all, and removing the possibility outright would take away something
that has always worked.

A directory that is *itself* already a project is untouched by this —
that case is adoption, and it already has its own rules.

## Acceptance criteria

1. Creating inside an existing project's tree is refused, and names
   the enclosing project and its directory.
2. The refusal writes nothing at all.
3. `--nested` allows it deliberately.
4. Creating beside a project, or anywhere with no project above, is
   unaffected.
5. Re-running creation on a directory that is already a project keeps
   its existing behaviour.
6. Both creation commands behave the same way, since both had the
   defect.
