# DD-464

## Title

Onboarding sets up the reminders, and can be run again.

## Epic

EPIC-457 — stale-card reminders.

## Owner decisions this implements

- Settled point 9 and 13: onboarding asks four things about the
  automation — the collector's own name (defaulted from the project,
  editable, and prefixed with `tira.` by Developer Dashboard when it
  registers), which coding agent, the session id, and the heartbeat —
  plus one default staleness threshold.
- Settled point 9: **no heartbeat means no collector.**
- Settled point 10: onboarding is **re-runnable**, pre-filling every
  answer from what the project already stores, so a project onboarded
  earlier gains the new settings by pressing enter through it.
- Settled point 18: when no coding agent is installed, **that part of
  onboarding never appears** — there is nothing to configure and
  nothing that could deliver.

## Design

- The five settings live in the project file beside the name, and every
  one is also settable non-interactively on `tira.project.update`, so
  the wizard is a convenience over a surface that stands on its own.
- The threshold question is asked whether or not an agent is installed:
  it decides what `tira.stale` reports, which is useful with no
  automation at all.
- Whether a coding agent is installed is discovered once, through a
  seam a test can drive, so both paths are proven rather than one being
  whatever the machine happened to have.
- Re-running loads the stored values as defaults before the first
  question. If the answer to the directory question names a different
  project, the defaults are loaded again from that one, so pressing
  enter never silently carries one project's settings into another.
- Clearing a setting is explicit: an empty value removes it, which is
  how the collector is turned off again.

## Acceptance criteria

1. Each setting stores, reads back, and is refused when invalid without
   changing what was already there.
2. An empty value clears a setting.
3. An unknown coding agent is refused and names the ones supported.
4. Re-running onboarding on an existing project pre-fills every answer,
   and pressing enter through it changes nothing.
5. Answering a different directory reloads the defaults from that
   project rather than carrying the first one's over.
6. With no coding agent installed, the agent questions never appear and
   onboarding still completes.
7. With one installed, they appear and what they collect is stored.
8. The collector name defaults from the project name.
