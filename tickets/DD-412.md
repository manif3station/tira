# DD-412

## Title

Own the text-attachment rendering: themed viewer pane instead of the
browser's default plain-text document.

## Method

Browser BDD (Playwright) under the Mandatory Problem-Solving Loop.

## Problem-Solving Loop record

1. **Expected:** a text attachment opened in the viewer is readable in
   every color scheme.
2. **Problem:** owner screenshot (message 2875, a real ZSD-138 file):
   white text on a white canvas — invisible.
3. **Root cause:** the viewer loaded text files into an iframe and let the
   browser's default plain-text stylesheet render them. In dark mode that
   stylesheet draws white glyphs, while the dialog's CSS forces a light
   iframe background — two uncoordinated styling authorities.
4. **Reproduction:** a dark-`colorScheme` Playwright context opening a
   text attachment; pre-fix the content is browser-styled inside the
   iframe (no owned text pane exists).
5. **Pre-fix comparison:** the owned text pane selector matches nothing.
6. **Fix:** the viewer fetches text-like attachments itself and renders
   them into its own `<pre class="card-viewer__text">` with the dialog's
   dark theme — deterministic colors in every scheme, still pure
   `textContent` (nothing can execute). Images keep `<img>`, PDFs keep
   the iframe (the PDF plugin owns its own contrast), other types keep
   the download link.
7. **Re-run:** the dark-scheme reproduction shows the file's text inside
   the themed pane with the dialog ink color.
8. **Guard:** the Playwright viewer scenario asserts the pane, its
   content, and that text no longer routes through the iframe.
