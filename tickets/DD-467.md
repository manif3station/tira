# DD-467

## Title

Onboarding collected the reminder settings and then did nothing with them.

## Source

Owner, message 3076, after running `tira.onboard` again on a real
project. Four problems, all reproduced before changing anything.

## The defects

1. **The interval is asked twice.** Onboarding asks "minutes before a
   card counts as stuck" and then "minutes between reminder checks".
   They are genuinely different — one decides when a card is stale, the
   other how often anything looks — but to the person answering they
   are two boxes wanting a number of minutes, and he read the second as
   a repeat of the first. My rationale does not matter here: if the
   person filling it in cannot tell two questions apart, that is the
   defect.

2. **The collector name goes nowhere.** Onboarding writes it into the
   project file and stops. Registering the job with Developer Dashboard
   is a separate command I built and never called, so filling the name
   in during onboarding produced no collector anywhere. This is the
   worst of the four: it looks like it worked.

3. **The collector cannot be started by the name he typed.** A
   consequence of 2, plus the registered name is `tira.<name>` while he
   typed `<name>`, so even once registered the name he remembers is not
   the name that starts it.

4. **The first question is not pre-filled.** Onboarding asks for the
   directory first precisely so everything else can be pre-filled from
   the project there — but the directory itself defaults to `.`, so
   re-running it anywhere other than the project root means typing the
   path before any of that helps.

## Fix

1. Ask once. The staleness threshold is the meaningful number — it is
   what decides when a card is stale and it can be overridden per
   column — so that is the question. The heartbeat defaults to it,
   since there is no point looking more often than the shortest window
   that could make anything stale, and `--heartbeat` still tunes it for
   anyone who wants to. The summary states what it chose rather than
   hiding it.

2. Onboarding registers the collector itself when it has both a
   heartbeat and a session, through the same validated path
   `tira.collector.install` uses.

3. It then prints the name it actually registered and the command that
   starts it, so the name he remembers is the name that works.

4. The directory question defaults to whatever project is already
   resolvable — `TIRA_HOME`, or one found from the current directory —
   falling back to `.` only when there is nothing to find.

## Acceptance criteria

1. Onboarding asks for a number of minutes exactly once.
2. The heartbeat is set from that answer, and an explicit heartbeat
   still wins.
3. Onboarding registers the collector when it has a heartbeat and a
   session, and does not when it has neither.
4. It reports the registered name and how to start it.
5. The directory question offers the resolvable project.
6. Registering through onboarding leaves other collectors alone, like
   the command does.
