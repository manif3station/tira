# DD-471

## Title

Questions on cards.

## Epic

EPIC-469. Implements settled points 1 to 4 and 9 to 13.

## Design

- Questions live on the card, in a `questions` list beside its comments
  and checklist, so they travel with it and need no second store.
- **Addressed by card reference alone.** The reference names the board
  through its prefix, and prefixes cannot collide inside a project, so
  asking for a board argument as well would be asking for something
  already known.
- **Status is derived, not stored**: a question with an answer is
  Answered, one without is New. Nothing to keep in step, nothing to
  drift.
- **Reading marks the answers read**, as he asked. That is a write on a
  read path, so it writes only when something actually changed.
- **The answer's mark is separate from having read it**: unmarked, ok,
  or not-ok. A cross settles nothing on its own — the output says so.
- **The time filter reads the answer's latest stamp when there is an
  answer, and the question's when there is not**, so catching up shows
  new answers as well as new questions.
- Every list carries an **instruction** saying what to do next, so an
  agent can tell from the output alone whether it is waiting or the
  owner is.

## Acceptance criteria

1. Ask, list, answer, update, remove and mark, all by card reference
   with no board argument.
2. A reference that matches no board is refused clearly.
3. Status is New until answered, Answered after, and cannot be set by
   hand.
4. Listing marks unread answers read, and does not rewrite the card
   when there is nothing to mark.
5. Marking takes ok or not-ok only, and marking not-ok says a new
   question is still required.
6. Filtering by status returns only that status.
7. Filtering by time uses the answer's stamp when answered and the
   question's when not.
8. The question's own stamp never changes when it is answered.
9. Every list carries the next-step instruction.
10. Questions work on all three boards.
