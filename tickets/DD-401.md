# DD-401: Resolve Private Projects Through DD Path Aliases

## Method

TDD + path-resolution security BDD + installed CLI ATDD.

## Expected happy path

- Existing relative and absolute project directories continue to work.
- A non-path project selector resolves through Developer Dashboard's registered
  path aliases for both the CLI option and environment selection routes.
- Tira validates the resolved directory normally but does not expose the alias
  target in successful output or alias-resolution errors.
- Unknown aliases and aliases without a Tira project exit 2 without fallback
  writes or filesystem mutation.

## Problem-solving evidence

Installed 0.12 rejected the real registered selector `tira-zen` through both
selection routes with exit 2 and `Cannot resolve project path`. The red tests
likewise failed both success routes while existing direct paths still worked.

The root cause was that discovery required the selector itself to exist before
any external namespace could resolve it. Tira now gives existing filesystem
paths precedence, then delegates non-path tokens to an injected resolver. The
CLI resolver constructs DD's installed PathRegistry, FileRegistry, and Config,
registers the layered aliases, and resolves through the authoritative DD API.
No command is spawned and no alias persistence format is duplicated.

The same real alias then returned project `Zenandi` through both routes with
status 0 and zero stderr. An unknown alias exited 2 with only its selector in
the error. Comparing every output stream against DD's resolved target found no
path disclosure.
