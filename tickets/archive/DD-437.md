## Title

(CA21).

## Method

## Problem

Owner instruction (messages 2951/2953): "Update the linkage section. To
use a table like list like the attachment section. To show ref - title -
status and sorted by priotiy."

## Design

- Every linked ref renders as a `card-linkage-table__row`: ref chip,
  live title, and column-status pill, with the existing unlink/remove
  buttons and add controls untouched (all `data-linkage-*` and
  `data-link-remove` payload contracts preserved).
- Row details come from the existing `/record` provider — summary board
  data only carries refs and titles — with a per-render promise cache so
  each linked ref costs one fetch; a failed lookup falls back to the
  board summary or an em-dash, never a broken row.
- Rows sort by priority descending as details arrive (unknown priority
  last, ties by ref); typed links keep their relationship label in a
  `--typed` row variant whose grid keeps the ref chip compact — a
  visual-review catch: the first screenshot showed the typed ref chip
  stretched, and the eyeball pass also caught a stale-fixture trap
  (static fixtures bake the renderer; regenerate before re-checking).
- The dialog-open guard in the Playwright suite now expects the lazy
  record read plus three linked-row lookups.
