# DD-425

## Title

Omit empty fields by default on the CLI read surface (CA15).

## Method

Engine TDD + CLI ATDD, red-first (`t/26-omit-empty.t`).

## Problem

EPIC-424: a record with thirty-six keys, twenty of them empty strings or
empty arrays, spends most of its size saying nothing. Absence is already
representable by omission.

## Design

- Engine `_is_empty_value`: undef, `''`, `[]`, or a hash whose every
  value is empty by the same rule (covers `scope` and blank linkage).
  Booleans and numbers — including `false` and `0` — are never empty.
- Pruning happens inside the existing projection layer when the caller
  passes `omit_empty`; a field named in `--fields` is exempt, so an
  explicit question always gets an explicit answer.
- The CLI turns `omit_empty` on by default for show, list, and export;
  `--include-empty` restores the fixed-key shape. Other commands exit 2
  on the flag instead of silently ignoring it.
- Internal engine callers and the browser dialog never pass the flag and
  are untouched.

## Acceptance

- empty string/array/null/recursively-empty-hash fields omitted; set
  values including numerics survive; ref and computed column survive
- engine default (no flag) returns the full shape; CLI default omits;
  `--include-empty` restores exactly
- selected-but-empty fields stay visibly null; export envelope keeps its
  count; full existing suite passes unchanged
- Docker tests pass; coverage `100.0%`; taint gate passes; `cover_db`
  cleaned
- `SKILLS.md` (signatures, omission contract, UC-042 note, exactly 100
  use cases), `docs/commands.md`, `Changes`, `VERSION 0.36`, tickets,
  commit, and push complete
