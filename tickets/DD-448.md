# DD-448

## Title

`tira.project.new` with no arguments guides the user through the setup.

## Method

CLI ATDD, red-first (`t/41-project-wizard.t`), with the prompt stream
injected so the guided flow is testable without a terminal.

## Problem

Owner request: running `tira.project.new` bare should ask the questions
rather than print a usage error — the same questions he wrote out by
hand (name, directory, users, the three reference prefixes, whether all
three boards share one column set, and the columns themselves).

## Design

- **It must never hang.** A wizard that reads standard input is a trap
  for scripts and agents, which is where most invocations come from. The
  guided flow starts only when standard input is a terminal; without one
  the command behaves exactly as before and exits 2 with its usage
  error. `--interactive` forces the flow, and an injected input handle
  is how the tests drive it.
- Questions are asked in the owner's own order and phrasing, including
  "Do all three boards use the same columns? [Y/n]".
- Any flag already given becomes that question's default, so the wizard
  completes a partial command line rather than starting over.
- Invalid answers re-ask with the reason rather than aborting — that is
  the entire point of a guided flow — while end-of-input aborts cleanly
  and creates nothing.
- A summary is shown and confirmed before anything is written.
  Declining exits 1 (a content-specific negative: nothing was created)
  and leaves no project.
- Answering "no" to the shared-columns question must mean something, so
  the engine gains per-board column sets (`--sow-columns`,
  `--epic-columns`, `--ticket-columns`) falling back to `--columns`.
  Without that, the question would be a lie.
- No new dependency and no terminal control codes: prompts are plain
  reads and writes, so the command stays taint-clean and spawns nothing.

## Acceptance

- bare invocation on a terminal asks every question and creates the
  project from the answers; bare invocation without a terminal exits 2
  unchanged and never blocks
- flags pre-fill defaults; `--interactive` forces the flow
- invalid name, prefix, and confirmation answers re-ask; end-of-input
  aborts with nothing created
- answering "no" to shared columns applies a different column set per
  board
- declining the confirmation exits 1 and creates nothing
- Docker tests pass; coverage `100.0%`; taint and primitive-scan gates
  pass; `cover_db` cleaned
- `SKILLS.md`, `docs/commands.md`, `README.md`, `Changes`,
  `VERSION 0.57`, tickets, BACKLOG, commit, and push complete

## Change during the work

The guided flow was first attached to a bare `tira.project.new`, guarded
by a terminal check. The owner moved it to its own command,
`tira.onboard`, which is better: the guard disappears entirely, because
`project.new` now never prompts under any circumstance and `onboard` is
only ever invoked deliberately. Nothing automated can be left waiting,
and there is no terminal-detection behaviour to reason about or test
around.
