# DD-456

## Title

Ten cards a column with a reveal button, and a keyword filter on the
board control.

## Method

Renderer-contract TDD + provider/HTTP ATDD + Browser BDD.

## Problem

Owner request: a column should show its first ten cards with a button to
reveal more, and the board control should carry a keyword filter that
narrows the board over AJAX. On his board a single column holds a
hundred cards, so the whole page is a wall of text before anything can
be found in it.

## Design

- One render pass owns filtering, paging, and the counts, so the three
  can never disagree. Every trigger — first paint, live refresh, sort,
  drag, reveal, filter — calls the same function.
- Paging is per column and by reveal: ten to begin with, then ten more
  each press, with the button saying how many remain. Cards are hidden
  rather than removed, so a hidden card is still there for the filter,
  the counts, and the sort.
- The count badge keeps reporting the column's real total (the filtered
  total when a filter is on), not the visible slice. A badge that
  counted what happens to be on screen would be worse than no badge.
- The filter asks the server rather than matching the titles already in
  the page: the engine's search reads descriptions too, so typing a word
  that appears only in a card's body still finds it — which is the whole
  point of asking. Input is debounced, an empty box clears the filter,
  and a failed request narrows to nothing rather than silently showing
  everything.
- Filtering resets paging, so the first ten *matches* are shown rather
  than the first ten cards that happen to match.

## Honest note on the guard

The filter's browser guard drives the function the input is bound to,
not the keystroke. Synthetic key events did not fire the debounce
reliably in this harness, and rather than weaken the assertion or
pretend, the guard exercises what matters — the request, the response,
and what the board then shows — while a renderer assertion pins the box
being wired to that function. The paging guard is a genuine end-to-end
interaction: it counts visible cards, presses the button, and counts
again.

## Acceptance

- the count badge stays the column total
- the filter requests the server, shows only matches, and clears
