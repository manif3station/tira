# DD-427

## Title

Per-record content hashes and conditional reads (CA05, CA06).

## Method

Engine TDD + CLI ATDD, red-first (`t/28-content-hash.t`).

## Problem

EPIC-424: a caller that has seen a record cannot tell whether it changed
without downloading it again; even with a hash it must receive a body to
learn that nothing happened. Timestamps distinguish less than hashes: a
touched-but-identical record looks changed.

## Design

- `_record_content_hash`: SHA-256 over the canonical JSON of every
  meaningful field including the computed `column`, excluding only
  `last_updated` (and itself) — a no-op write keeps its hash, any field
  change, comment, attachment, or move alters it. Documented opaque.
- `content_hash` joins the selectable-field list and is computed only
  when named in `--fields` — reads that do not ask stay exactly as
  small as before.
- `_board_hash`: SHA-256 over `ref:hash` lines of the full result set;
  export returns it whenever hashes are requested and uses it for
  `--if-changed`, always computing from full records so projection can
  never skew it.
- `--if-changed HASH` (show and export): unchanged → `{"unchanged":
  true}` with CLI exit 1 (the tool's documented content-negative
  status; the marker also distinguishes it from a genuine empty result);
  changed → the normal, projectable payload with exit 0; malformed hash
  → exit 2, because a bad token must never be read as "changed".
  Combined with `--since`, the stricter suppression wins. The owner
  document's expectation section asks the exit status to distinguish
  the cases while use case 6 says exit 0 — the expectation and Tira's
  existing exit contract (1 = content-specific negative) win; recorded
  here as the deliberate resolution.
- Conditional reads never write; other commands refuse the flag with
  exit 2.

## Acceptance

- hash stable across reads and no-op writes; changed by field edits,
  comments, attachments, and moves; hex-opaque; absent unless selected
- export board hash stable across quiet exports, returned alongside
  per-record hashes, collapsing to the unchanged marker on match
- conditional show: marker + exit 1 unchanged, full record + exit 0
  changed, exit 2 malformed, composes with `--fields` and `--since`
- refused outside show/export with exit 2 naming where it applies
- Docker tests pass; coverage `100.0%`; taint gate passes; `cover_db`
  cleaned
- `SKILLS.md` (signatures, hash/conditional contract, UC-043 extended,
  exactly 100 use cases), `docs/commands.md`, `Changes`, `VERSION
  0.38`, tickets, commit, and push complete
