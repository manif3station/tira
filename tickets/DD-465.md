# DD-465

## Title

Apply a whole column layout in one call.

## Epic

EPIC-457 — settled point 15 (the column editor), engine half.

## Owner decision this implements

Point 15: a button on each board control opens a modal shaped like the
card modal but showing the board's structure — add a column, remove
one, drag them into a different order, and set each one's notification
time. Scoped by the owner as its own ticket, to ship after the
notification work it configures. This is the half that ticket needs
underneath it: one call that takes the layout the editor is showing and
makes the board match.

## Design

A drag-reorder editor knows the layout it wants, not the sequence of
steps that gets there. Asking it to work out which columns to add,
which to remove, and what order to reorder into would put the hardest
part of the feature in the browser. So `column_apply` takes the desired
list and works out the difference itself.

**Atomicity, stated plainly rather than glossed over.** Removals move
cards between folders and each already takes the project lock, and the
lock is not reentrant, so they run first, one at a time. Everything
else — additions, order, labels, thresholds and watched flags — is a
single write of the board config under one lock. So the editor cannot
half-apply a reordering, but a run that fails partway through several
removals will have made some of them. The call reports exactly what it
did for that reason.

## Acceptance criteria

1. Reordering, renaming labels, thresholds and watched flags all apply
   in one call.
2. Columns absent from the desired list are removed and their cards
   relocated, exactly as removing one at a time would.
3. Columns present in the desired list but not on the board are added.
4. A protected column left out of the list is refused, and nothing is
   changed.
5. A duplicate or invalid name is refused before anything is written.
6. The call reports what it added, removed, reordered and updated.
7. Applying the layout the board already has changes nothing and says
   so.
8. Available to the browser through its own provider and route.
