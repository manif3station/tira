# DD-446

## Title

`tira.project.new` — bootstrap a whole project in one command.

## Method

Engine TDD + CLI ATDD, red-first (`t/40-project-new.t`).

## Problem

Owner request: onboarding a project the way he does it by hand takes 35
separate commands — create, two people, three ref prefixes, and eight
columns repeated across three boards — every one of which must be typed
with the right slug, the right label, and in the right order. It is
tedious, easy to get wrong, and the failure modes are silent: a
mistyped slug is refused, but a forgotten prefix is not noticed until
the first record carries the wrong reference, by which time the board
counter has already advanced and cannot be rewound.

## Design

- One command creates the project, its people, its per-board reference
  prefixes, and a shared column set: `tira.project.new`.
- **Human text in, slugs out.** Columns are given as they are written —
  `--columns "Backlog, Planning, In Progress, Done / Release"` — and the
  command derives the slug (`done-release`) while keeping the original
  text as the label. That removes the single most error-prone step of
  the manual sequence and matches how the owner writes the list.
- Names that already exist as protected defaults (Backlog, Discard) are
  skipped rather than refused, so the natural full list works verbatim
  and the command is safe to re-run.
- Prefixes are three explicit options (`--sow-prefix`, `--epic-prefix`,
  `--ticket-prefix`) rather than a packed pair grammar, because
  `--prefix` is already a single-valued option owned by `board.refs`
  and widening it would silently turn that value into an array for
  every existing caller.
- Likewise `--members` and `--columns` are new plural options; the
  existing `--person`, `--column`, and `--label` all carry different
  established grammars and arities.
- **Everything is validated before the first write.** The documented
  exit-status contract says validation failure creates no mutation, and
  the engine's project lock is not re-entrant, so the command cannot be
  one transaction — it is a sequence of locked calls. Validating names,
  member ids, every derived slug, every prefix, and the digit count up
  front is what keeps a rejected invocation from leaving half a project.
- Prefixes are applied before anything can create a record, because a
  board counter never goes backwards: setting a prefix after the first
  record yields `M5S-002`, not `M5S-001`.

## Acceptance

- one invocation yields the project, its people, the three prefixes, and
  the shared columns in the given order on all three boards
- column names are slugified from human text with labels preserved;
  existing/protected columns are skipped; re-running changes nothing
- invalid name, member, column, prefix, or digit count exits 2 and
  writes nothing at all
- `-o json` returns a structured summary of what was created
- Docker tests pass; coverage `100.0%` statement and subroutine; taint
  and primitive-scan gates pass; `cover_db` cleaned
- `SKILLS.md` (signature, contract, one existing use case rewritten —
  never a 101st), `docs/commands.md`, `README.md`, `Changes`,
  `VERSION 0.56`, entrypoint count 85 → 86, tickets, BACKLOG, commit,
  and push complete

## Adversarial review

Twenty-three agents attacked the command before release; every claim was
then independently re-run by a separate verifier whose job was to refute
it. Two high-severity defects survived and are fixed:

1. **Colliding reference prefixes could brick a project on its first
   command.** `--sow-prefix TKT` was accepted even though `TKT` is the
   ticket board's default, so both boards minted `TKT-001`. A duplicate
   reference cannot be read, moved, updated, or repaired — `record.show`
   dies permanently, `project.validate` still reports valid, and there
   is no delete command. The whole effective prefix set, including
   boards the caller did not name, is now checked for uniqueness before
   anything is written.
2. **An existing project at the target directory was silently adopted
   and mutated**, ignoring the given name and overwriting prefixes on
   populated boards. Adoption is now limited to a project of the *same
   name*, and a prefix change is refused once a board holds records,
   because a counter never rewinds and the board would end up holding
   two reference series.

Also fixed: an over-long column name passed slugification and then died
inside `make_path` after the project and people were written (the bound
now sits in validation, and in `_valid_slug` so `column.add` inherits
it); and an explicitly empty `--sow-prefix ''` was silently ignored
rather than refused.

Recorded, deliberately not changed: adding these options makes the
undocumented Getopt::Long abbreviations `--ti` and `--col` ambiguous.
Two independent verifiers judged this acceptable — abbreviations are
undocumented, nothing in the repo or manual uses them, and the failure
is loud (`Option ti is ambiguous`, exit 2) rather than silent. Renaming
the options to protect an unused shorthand would make the documented
surface worse.

Known and left alone: without `--dir` the project is created in the
current directory, which can nest one project inside another. That is
pre-existing `project.create` behaviour, identical in both commands, and
is raised as DD-447 rather than changed here.
