# DD-490

## Title

A voice note on a question, playable from the board.

## Source

Owner: after writing the question, its reason and its choices, an agent
can attach a voice note. It is stored as an ordinary attachment, and on
the dashboard a button plays it — reading out the question, the reason
and the choices.

## The constraint that shapes it

Tira's engine invokes no shell and no external process, which is why
the coding agent is only ever run by the collector. So **Tira does not
speak the text**: the agent produces the audio and hands Tira a file.
Tira stores it, serves it, and gives the board a way to play it.

That division is not a limitation to work around — it is the reason the
whole suite passes under taint mode and why the engine can be trusted
inside another tool.

## Design

- A question can carry a voice note: `question.ask --voice FILE`, and
  `question.voice --id Q-NNN --file FILE` to add or replace one later,
  since a question can be decomposed after the fact (`DD-482`) and its
  audio will need redoing when it is.
- Stored through the existing content-addressed attachment machinery,
  so a voice note is deduplicated and served by the route that already
  serves attachments. Nothing new to secure.
- The question records the sha and extension, like every other
  attachment reference.
- The dashboard question block gains a play control that uses the
  existing audio element rather than a second player.

## Acceptance criteria

1. A question can be asked with a voice note in one command.
2. One can be added or replaced afterwards.
3. It is stored as an ordinary attachment and deduplicated.
4. A file that is not audio is refused, naming what is accepted.
5. The board plays it; a question without one shows no control.
6. Removing is possible, since a wrong recording should not be
   permanent.
7. Documented in both manuals.
