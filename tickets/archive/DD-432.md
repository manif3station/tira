# DD-432

## Title

Batch reads on show (CA19).

## Method

Engine TDD + CLI ATDD, red-first (`t/33-batch.t`).

## Problem

EPIC-424: reading six tickets means six invocations, six process starts,
six payloads. The refs are known in advance and the work is one query.

## Design

- `record_show_many`: validates the projection and project once (loud,
  whole-call failures), then reads each unique ref in request order;
  the result is `{records, order, count}` keyed by ref. A ref that
  fails lookup becomes `{ref, not_found: true}` without losing the rest.
  At most 100 refs, refused clearly beyond. Ref resolution is
  type-agnostic, so batches cross types naturally.
- CLI: `--ref` became repeatable (the last value keeps serving every
  single-ref command exactly as before); `--refs` takes a comma list;
  both compose. More than one ref routes show to the batch and any
  other command to exit 2. `--if-changed` on a batch is refused with a
  pointer at the cheaper `export --fields ref,content_hash` sweep — the
  owner document's per-ref conditional (UC9) trades a positional
  hash-to-ref pairing footgun for nothing the hash sweep does not
  already provide, recorded here as the deliberate resolution.
