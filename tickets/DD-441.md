# DD-441

## Title

Column card counts and add-card from the board.

## Method

Renderer-contract TDD + provider/HTTP ATDD + Browser BDD (Playwright)
and a visual review.

## Problem

Owner instruction (Telegram message 2978): two things are unreachable
from the UI — how many cards a column holds, and any way to create a
card. He asked for a count beside the column name, shown only when the
column has cards, and an add-card control opening the same dialog with
an empty form, no reference until submission, and only the title
mandatory.

## Design

- **Counts** render as a badge in each column header and are filled from
  the board's own DOM rather than a server number, so they stay correct
  after a refresh, a drag between columns, or a creation without any
  extra request. Zero hides the badge instead of printing `0`.
- **Add-card** appears under each column's cards on live boards only —
  static `-o table` output has no server to post to, so rendering the
  control there would be a lie.
- **New-card mode** reuses the dialog: the header states the type, the
  target column, and that the reference is assigned on save; the form
  carries title (required), description, priority, and assignee. Every
  other field is editable on the card once it exists, which keeps the
  creation form short without hiding anything.
- Validation is the dialog's own (`noValidate` on the form) so the
  message appears in the same error surface as every other dialog
  failure rather than in a browser bubble.
- A half-filled new card counts as active editing and the refresh cycle
  skips a dialog with no ref, so DD-438's live refresh can never wipe
  work in progress.
- Creation posts to a new `/create` route and provider that calls the
  ordinary `create_record` (then `record_move` for a non-backlog
  column), so unknown columns, unknown assignees, and missing titles are
  refused by the same engine rules as the CLI. The dialog then switches
  to the created card.

## Process note

The implementation was written before its tests here, unlike the rest of
this series. Rather than claim a red-first run that did not happen, the
new contract tests were verified by stashing the implementation and
running them: `t/19` failed tests 6–12 and `t/16` failed its count and
add-card assertions, then passed with the implementation restored.

## Acceptance

- counts render per column, hidden at zero, correct after refresh and
  drag; static output has no add-card control
- add-card opens new-card mode with no ref; an empty title is refused in
  the dialog and posts nothing; a filled form posts type, column, title,
  and the optional fields, then the dialog shows the created card
- provider refuses missing title, unknown column, unknown assignee, and
  malformed payloads; empty optional fields are left unset
- Docker tests pass; coverage `100.0%`; taint gate passes; `cover_db`
  and fixtures cleaned; Playwright ×3 green; both features reviewed
  visually
- `SKILLS.md` (contract and UC-008), `Changes`, `VERSION 0.54`,
  tickets, BACKLOG, commit, and push complete
