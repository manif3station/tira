# DD-429

## Title

The `--brief` preset and default long-text truncation (CA08, CA09).

## Method

Engine TDD + CLI ATDD, red-first (`t/30-brief-truncate.t`).

## Problem

EPIC-424: four reads in five want the same five fields, and descriptions
reach twelve thousand characters while gate logs and evidence grow
without bound — a caller wanting the first line pays for all of it.

## Design

- `--brief` maps inside `_field_projection` to the documented list
  `ref,title,column,sdlc_gate,assignee` — a literal shorthand for the
  equivalent `--fields`, so every projection property (null visibility,
  ref retention) is inherited, with the title cut at a stable 72
  characters plus an ellipsis. `--brief` with `--fields` dies.
- `_truncate_text_slot` cuts a string at the limit, appends an ellipsis,
  and marks `<key>_truncated`/`<key>_length`; zero omits the text but
  keeps the markers; short values gain no noise. Applied to the three
  long scalar fields and to each gate entry's `details` and evidence
  entry's `summary` — the unbounded growers.
- Truncation runs after hashing and projection: presentation only, so a
  truncated read and a full read agree about change.
- CLI defaults `truncate` to 2000 on show/list/export unless `--full`;
  `--truncate N` chooses; `--full` with `--truncate` and negative limits
  exit 2. Engine stays opt-in, so internal and browser callers are
  untouched.
- The owner document's UC4 mentions `tira.dashboard --brief`; the board
  dashboard is already a summary view by design, so no flag is added —
  recorded here and in SKILLS.md rather than silently skipped.

## Acceptance
