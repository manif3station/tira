# DD-397: Add Migration-Scale Read And Correction Tools

## Method

ATDD + migration BDD + security TDD.

## Objective

Replace hundreds of per-record process launches with one-call reads, previewed
bulk corrections, field-aware search, and append-only log annotations.

## Acceptance criteria

- Record list accepts `--full` without changing its compatible array shape.
- Export returns every SOW, epic, and ticket with column state in one object.
- Search with `--field` reports the exact matching field and value.
- Import accepts a ref-keyed JSON object, previews exact field changes with
  `--dry-run`, and applies all records transactionally.
- Replace previews field-level regex changes and applies only mutable content.
- Gate and evidence entries have stable IDs and append correction annotations
  without rewriting original observations.
- No polling watcher, general gate/evidence mutation, undo, or changelog is
  introduced.
- Docker tests retain 100% statement/subroutine coverage, followed by the
  taint/perlsec, documentation, commit, and push gates.

## Problem-solving loop evidence

### Expected happy path

- Full list and export return complete records with current columns in one
  process each.
- Field search returns the exact matching field paths and values.
- Import and replace dry runs report changes without persistence; apply produces
  those changes exactly.
- A mixed valid/invalid import writes nothing.
- Gate/evidence annotations retain the original observations and append notes.

### Root cause

The released CLI had only per-type list/search primitives: it rejected `--full`
and `--field` and shipped no export, import, replace, or annotation entrypoints.
The engine likewise lacked bulk transaction/diff and log-annotation methods.

### Reproduction and before result

Against the installed pre-0.09 `d2` skill in a disposable project:

- `d2 tira.ticket.list --full -o json` exited 2: unknown option `full`.
- `d2 tira.export -o json` exited 1: command not found.
- `d2 tira.search --text Jira --field description -o json` exited 2: unknown
  option `field`.

### After result

The same workflows through the 0.09 working-tree CLI returned three exported
records with columns, one full ticket with its Backlog column, and two
description hits with exact field names. Import dry-run reported one change and
left `See Jira ABC-3` intact; apply persisted `Local reference`. Replace dry-run
left that value intact and apply reported one change. Gate/evidence originals
remained `Old Jira URL`/`Old Confluence URL` while annotations contained the
local corrections. A mixed import exited 2 on missing `ZZZ-999` and retained
the valid ticket title `Migration ticket`.

### Regression guard

`t/13-migration-tools.t` permanently covers the expected one-call reads,
field hits, dry-run/apply comparisons, atomic rejection, nested replacement,
append-only annotations, CLI routes, aliases, and negative validation paths.
