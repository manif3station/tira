# DD-433

## Title

A first-class diff command (CA13).

## Method

Engine TDD + CLI ATDD, red-first (`t/34-diff.t`).

## Problem

EPIC-424: every watcher written against Tira implements the same
snapshot-compare-report loop, each slightly differently and each wrong
somewhere. It is the tool's job.

## Design

- `diff_records` with exactly one baseline (`since` or `snapshot`,
  both/neither exit 2). Since mode reuses the changed-since scan and
  reports per record: kind (`added` when `created_at` clears the
  threshold, else `changed`), current column/gate/title, and new-comment
  ids — act-without-re-read — plus `now` for gap-free chaining.
- Snapshot mode reads a stored full export (`{records}` envelope or a
  bare array), indexes by ref, and compares every schema field except
  the volatile/computed ones: scalars carry `before`/`after`; comments
  report `added` ids or an explicit `changed` marker for edits;
  structural fields carry `changed: true`; refs only in the snapshot
  become `removed` entries, so deletion never reads as quiet.
  Omitted-vs-empty snapshot keys compare equal via the CA15 emptiness
  rule, so default-CLI snapshots do not false-positive.
- `--fields` scopes a snapshot comparison (refused with since, where
  previous values do not exist); `--count` answers whether to look; an
  empty diff is an explicit `{changes: [], count: 0, now}`.
- The owner document's `--type comment` example collides with Tira's
  record-type `--type`; comment-only watching is served by
  `--fields comments` on a snapshot diff, recorded here as the
  deliberate resolution. Diff never writes; snapshots are stored by the
  separate export call (UC10 honored by construction).
- New `cli/diff` entrypoint; t/03's executable count moved 83 → 84.

## Acceptance
