# DD-436

## Title

Opt-in read-through cache with write invalidation (CA18).

## Method

CLI ATDD, red-first (`t/37-cache.t`), correctness-first per the owner's
closing caution.

## Problem

EPIC-424: a single sweep may call export several times within a minute
for different purposes — each a full read of data that has not changed
between them.

## Design

- Disabled by default; `--cache-ttl N` (>= 1 second) enables per call on
  read commands only; `--no-cache` is the explicit bypass; mutations and
  zero ttls exit 2. The lookup itself only engages for a valid ttl — a
  zero ttl with a same-second entry would otherwise hit before
  validation, which the red loop caught.
- Entries live under the project's own `.tira/cache` (never shared
  temp), keyed by SHA-256 of the full canonical argument set including
  format, `--since`, and `--if-changed`, so no two queries can share an
  entry and the change-detection flags cannot be silently defeated.
- Validity is ttl AND a board fingerprint: hi-res mtimes of the project
  config, board directories, column directories, and attachment store.
  Every mutation renames into one of those directories, so any write
  invalidates immediately — read-your-own-writes by construction.
- A hit prints `tira: served from cache` on stderr (never invisible)
  and replays the stored exit status, so a cached unchanged marker
  still exits 1. Stores are atomic (temp + rename), bytes base64-coded
  inside JSON. A corrupt or unreadable entry warns and falls back to a
  live read; a failed store warns and the live result stands — the
  cache can never break the tool.

## Acceptance

- identical bytes on hit with the stderr report; workspace-local
  storage; bypass; immediate post-write freshness; per-argument keys;
  ttl expiry; corrupt fallback with warning; mutation and zero-ttl
  refusals
- Docker tests pass; coverage `100.0%`; taint gate passes; `cover_db`
  cleaned
- `SKILLS.md` (cache contract, UC-043 extended, exactly 100 use cases),
  `docs/commands.md`, `Changes`, `VERSION 0.47`, tickets, commit, and
  push complete
