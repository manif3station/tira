# DD-414

## Title

Last-modified sort collapses after the first live refresh.

## Method

Browser BDD under the Mandatory Problem-Solving Loop.

## Problem-Solving Loop record

1. **Expected:** the Last modified sort keeps cards newest-first at all
   times, including after live refreshes.
2. **Problem:** owner report: cards in a column are not sorted by last
   modified when that sort is selected.
3. **Root cause:** the live board's `/data` payload deleted `_mtime`
   (the include flag keyed off the output format, and the data callback
   overrides output to build JSON), and the card rebuilder read
   `updated_at`/`last_updated` fields the summary payload never carries —
   every rebuilt card stamped zero and the sort fell through to the
   reference tiebreak. The server-rendered first paint sorted correctly,
   masking the bug until the first refresh.
4. **Reproduction:** staggered-mtime fixture; post-refresh order was
   reference order with all-zero stamps.
5. **Pre-fix comparison:** server paint newest-first; post-refresh
   reference order — mismatch confirmed.
6. **Fix:** data callbacks request `include_mtime` explicitly (honored by
   `_invoke`); `buildCard` prefers `_mtime` with the old fallback.
7. **Re-run:** newest-first with nonzero stamps after refresh.
8. **Guard:** permanent post-refresh order assertion in the browser
   scenario.

## Status

Done — shipped in 0.25.
