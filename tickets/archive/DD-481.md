# DD-481

## Title

Five things on a question, and a choice you can just click.

## Source

Owner, live, in three parts:

- the popup must show **five** things per question: the question, its
  choices, the reason it was asked, its status (New, Answered,
  Discard), and its answer with add **and edit**;
- on the dashboard "the user can just click on the choices, only need
  to answer if they pick other option";
- anything done on the dashboard "will directly translate to what the
  cli command whatever internal subroutine calls... so if any trigger
  logic won't missed".

## What was missing

I had built four of the five. Two gaps:

1. **Discarded questions were filtered out of the dialog entirely**, so
   the Discard status he named could never appear. They are shown now,
   struck through, because a question that was set aside still
   happened.
2. **An answer could only be read, never edited.** The box existed only
   for unanswered questions.

And the choices were a numbered list to read, not buttons to press.

## Design

- The choices are buttons. Clicking one answers with it, in one action,
  because picking a choice *is* the whole answer. **Other…** reveals
  the text box for anything else, so typing is the exception rather
  than the default.
- The box doubles as the editor: on an answered question it is
  pre-filled with the current answer and the button reads *Save
  answer*.
- Status is shown as its own label, and a discarded question is drawn
  struck through and faded rather than hidden.

## The guarantee, now enforced rather than assumed

His third point is the important one, and it was already true — the
browser providers call the same engine methods the CLI dispatches to.
But "already true" is not the same as "kept true", so `t/62` now does
the same work from both sides and compares every consequence: the
stored answer, its stamp, whether the card still counts as waiting,
whether an all-clear is owed, and when the reminder resumes. If the
board ever took a shortcut, a trigger would fire for one card and not
the other and that test would fail.

## Acceptance criteria

1. The panel shows all five things for every question.
2. Discarded questions appear, struck through, with that status.
3. Clicking a choice answers with it.
4. Other… reveals the box; it is out of the way otherwise.
5. An existing answer can be edited and saved.
6. The board and the command line produce identical consequences.
7. Both manuals document all of it.
