# DD-470

## Title

`tira.usage`, and two manuals that know about each other.

## Source

Owner, message 3134: `d2 tira.skills` prints `SKILLS.md` and
`d2 tira.usage` prints `docs/commands.md`; both should mention each
other. Asked for as groundwork before the question feature, whose
documentation has to land in both.

## The gap

`tira.skills` exists. `tira.usage` does not, so `docs/commands.md` — the
reference for every command and argument — can only be read by someone
who already knows the file is there and where to look. An agent working
through the dashboard has no way to reach it.

Neither document mentions the other, so reading one gives no hint that
the other exists.

## Design

- `tira.usage` prints `docs/commands.md`, exactly as `tira.skills`
  prints the manual: raw bytes, no formatting, no interpretation.
- Each document opens by naming the other and the command that prints
  it, so whichever one an agent reaches first leads to the other.
- The cross-reference in `SKILLS.md` must not disclose project
  selection, like everything else in that file.

## Acceptance criteria

1. `tira.usage` prints `docs/commands.md` byte for byte.
2. It fails clearly if the file is missing, rather than printing
   nothing and exiting cleanly.
3. `SKILLS.md` names `tira.usage` and what it is for.
4. `docs/commands.md` names `tira.skills` and what it is for.
5. Neither cross-reference discloses project selection.
