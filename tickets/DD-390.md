# DD-390: Add Record Metadata And Inactive-Person Lifecycle

## Method

TDD + BDD + ATDD.

## Objective

Implement the approved next-release metadata contract symmetrically for SOWs,
epics, and tickets, including singular ownership, planning metadata, generated
parent identity, and safe historical person retention.

## Acceptance criteria

- Store one nullable assignee and reporter ID; render their current names in
  human output.
- Store case-insensitive unique labels, zoned ISO 8601 start/due date-times,
  free-text SDLC gate/lifecycle, priority 1-5, one fix version, and affected
  versions.
- Generate one immediate parent from hierarchy or sub-item linkage and forbid
  direct parent mutation.
- Add activate/deactivate person commands. Inactive people remain historically
  visible but cannot receive new assignment or reporter references.
- Reject person removal while any historical record reference remains.
- Prove CLI and engine behavior in Docker with 100% statement and subroutine
  coverage, then pass the taint/perlsec gate.
- Update all required documentation, commit, and push release 0.03.
