# DD-480

## Title

The yellow showed for one second and then vanished.

## Source

Owner, live: "the yellow colour of the card only show 1 seconds of
yellow then turn back to normal colour". Also a re-read of
`tickets/REPORT-2026-08-09-question-list-human-output.md`, which turned
out to have one criterion still unmet.

## Two defects

### 1. The refresh wiped the colour it had just painted

The page is served as HTML with the waiting cards already yellow. A
second later the live refresh fetches `/data` and **rebuilds every
card** from that payload. The payload was built with a separate set of
options that never asked for question state, so every rebuilt card came
back unmarked and the yellow disappeared.

Exactly one second of yellow, which is what he described. The symptom
named the cause precisely: anything that survives the first paint and
dies on the first refresh is the refresh payload disagreeing with the
rendered page.

### 2. The question view did not name the card

The report asked for the card's title in that view "as it does in
`ticket.show`". I shipped `# Questions on VFT-001` — reference only. A
person reading it has no idea which card it is without going to look.
My own test asserted the heading matched the reference, so it passed
while missing the point of the criterion.

## Why the first test I wrote for this was worthless

My initial guard used the dialog fixture, which passes `--title` — and
titles already force the read that computes the flag. So it passed with
the fix removed. The real case is a board opened **without** titles,
which is how anybody opens one. The replacement drives the actual
command with the actual options and was confirmed to fail without the
fix.

## Acceptance criteria

1. A board opened with no titles still reports waiting cards in its
   refresh payload, so the colour survives.
2. It fetches no titles nobody asked for.
3. An explicit request for question state beats the format guess.
4. The question view names the card the way `ticket.show` does.
