# DD-493

## Title

A manual example that could not work, and a count that read as zero.

## Source

Two field reports from another agent, relayed by the owner.

## 1. `--file` versus `--voice` — twenty-seven failed attempts

The manual's example read
`tira.question.voice --id Q-007 --file X.ogg`. The command took
`--voice`. The agent tried twenty-seven times.

**The deeper fault was mine, not the documentation's.** Every other
command in Tira that takes a path calls it `--file`. I invented
`--voice` for this one. The agent's instinct was correct and the tool
was inconsistent, so `--file` is now accepted and documented, and
`--voice` still works for anyone who learned it.

## 2. A count that read as zero

`attachment.list` counted only files attached to the card. A file can
be on the card, on a comment, or a voice note on a question — so a card
whose files hung off comments reported **zero**, the agent read that as
failure, and only found the audio by digging a level deeper.

A count that says zero when files exist is a lie by omission. It now
looks in all three places and each entry says which one it came from,
because "three files" without "where" only moves the hunt.

## Why the tests did not catch the first one, which is the real lesson

The documentation test asserted that `--voice` appeared in the
questions section. A wrong example contains the flag too, so it passed.

The replacement runs every example in both manuals through the real
parser against a project that actually contains the references they
name. Getting there took three attempts, and each failure was
instructive:

1. Checking the flag exists **anywhere** — useless, because `--file`
   has always existed, just not on that command.
2. Checking for a rejection — useless, because the command did not
   reject anything. It ignored the flag and complained the file was
   missing.
3. Checking for the **contradiction** — being told to supply what you
   just supplied. That catches it, and it is the most confusing failure
   a tool can produce, so it is worth catching in general.

The fixture also had to contain `TKT-001` and `Q-007`, or every example
failed on a missing reference before reaching the flag under test —
which is how the first version passed against the very build it was
written to catch.

## Status

Done

## A defect this test introduced, and fixed

Running documented examples for real means running the ones that
write. The first run created a directory called `DIR]` in the
repository, from a placeholder in an example taken literally — owned by
root, because the suite runs in a container.

Every attempt now runs inside the throwaway project, so a stray write
lands somewhere that is deleted rather than in somebody's checkout. The
stray directory was removed with a disposable container, never `sudo`.

Worth stating plainly: a test that executes documentation is more
useful than one that reads it, and also more dangerous. Containing what
it can write is part of the cost of that usefulness.
