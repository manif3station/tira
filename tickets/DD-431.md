# DD-431

## Title

Server-side `--where` filtering on list and export (CA16).

## Method

Engine TDD + CLI ATDD, red-first (`t/32-where.t`).

## Problem

EPIC-424: "every ticket in backlog with no gate" means downloading every
ticket and filtering locally. The filtering is trivial; the download is
not.

## Design

- `_parse_where` validates once: `FIELD=VALUE` equality, `FIELD=` empty
  meaning empty-or-unset (the CA15 emptiness rule, so array and scalar
  absence read the same), `FIELD!=` both ways, `FIELD~VALUE`
  case-insensitive containment over array elements (a scalar field
  simply never matches — no crash, no error). Unknown fields and
  operatorless clauses die.
- Matching runs inside `record_list`'s scan on the full record plus
  computed column; `content_hash` and `attachment_count` are computed
  on demand when referenced and removed again unless separately
  selected. Export inherits, including under `--if-changed` (the board
  hash covers the filtered set).
- CLI `--where` repeatable on list and export; exit 2 elsewhere.

## Acceptance

- equality, emptiness both directions, inequality, containment,
  numeric-as-string equality, parent and computed-field filtering all
  behave per tests; clauses AND; composes with `--fields`, `--count`
- unknown fields and operatorless clauses exit 2 naming the problem
- Docker tests pass; coverage `100.0%`; taint gate passes; `cover_db`
  cleaned
- `SKILLS.md` (signatures, filter contract, UC-045 reworked, exactly
  100 use cases), `docs/commands.md`, `Changes`, `VERSION 0.42`,
  tickets, commit, and push complete
