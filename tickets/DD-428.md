# DD-428

## Title

Count-only and refs-only reads (CA07, CA17).

## Method

Engine TDD + CLI ATDD, red-first (`t/29-count-refs.t`).

## Problem

EPIC-424: questions about a number — how many parked, how many in a
column — cost every matching record today; questions about which
records match cost the records themselves.

## Design

- `record_list` answers `{count => N}` under `count` and a flat ref
  array under `refs_only`, in the existing stable ref order; projection
  is moot in both modes but field names still validate loudly.
- `export_records` delegates count mode to the list; `search` handles
  both modes at its envelope so they are never misread as list
  arguments, deduplicating refs across field-scoped hits.
- Documented precedence: count > refs-only > fields.
- CLI: `--count` on list/export/search, `--refs-only` on list/search,
  exit 2 elsewhere naming where each applies; `-o human` prints a bare
  number or one ref per line for direct shell use.

## Acceptance

- count composes with filters and since; zero is an answer; empty refs
  are `[]`, never null
- refs stable and deduplicated; search count counts hits, not records
- precedence honored; invalid field names still exit 2 in count mode
- Docker tests pass; coverage `100.0%`; taint gate passes; `cover_db`
  cleaned
- `SKILLS.md` (signatures, contract, UC-044 reworked, exactly 100 use
  cases), `docs/commands.md`, `Changes`, `VERSION 0.39`, tickets,
  commit, and push complete
