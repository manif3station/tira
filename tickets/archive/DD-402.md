# DD-402: Add A Metadata-Free Fast Dashboard

## Method

Performance TDD + output-contract BDD + filesystem-ordering ATDD.

## Expected happy path

- Default dashboard output reads column directories, not record JSON, and
  shows only card refs under configured columns.
- Cards are newest-first by file modification time, with ref order as a stable
  tie-breaker.
- `--title` reads each card once and adds its title without changing order.
- `-o json` retains the complete structured record dashboard contract.
- Discard inclusion, board filters, column order, and invalid-file rejection
  remain unchanged.

## Problem-solving evidence

The release 0.13 working-tree baseline rendered 240 cards in 13 columns in
1.06, 0.82, and 0.89 seconds and emitted 224,033 TOON bytes. Although DD-400
removed repeated scans, default output still decoded every complete JSON record.

The red gate failed nine assertions: four JSON reads instead of zero, full
record cards instead of refs, ref rather than mtime order, and no bare
`--title` support. The first scan-count guard was retained and strengthened to
require no recursive `record_list` call.

The fixed default took 0.28, 0.14, and 0.28 seconds and emitted 3,881 bytes.
`--title` took 1.03, 0.38, and 0.40 seconds and emitted 7,205 bytes; full JSON
took 0.46, 0.63, and 0.66 seconds and retained complete records. All modes
contained 240 cards in configured columns, sorted newest filesystem mtime first
with ref tie-breaking. Default mode performed zero JSON reads and title mode
exactly one per valid card.
