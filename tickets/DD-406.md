# DD-406

## Title

Render the browser card dialog as a Jira-style sectioned view with in-dialog
field editing and full comment management.

## Method

Engine/CLI TDD + HTTP ATDD + Browser BDD (Playwright)

## Problem

The live dashboard's card dialog shows the whole record as one
`JSON.stringify` blob. Users need a human-readable, section-by-section view
like Jira, the ability to change record details directly from the dialog, and
comment add/update/delete from the browser. The engine also has no comment
removal at all (CLI or browser).

## Acceptance

- clicking a card renders the ajax-loaded record section by section — header
  (reference, type, column, title), a details grid (assignee, reporter,
  priority label, labels, start/due dates, fix version, affects versions,
  SDLC gate, lifecycle, parent), long-text sections (description,
  problem/feature, solution needed, source), list sections (key details,
  deliverables, scope included/excluded, acceptance criteria, test steps,
  BDD, ATDD, checklist with item status, gate passing log, evidence,
  attachments, subitems, linkage), and comments (author, created/updated
  timestamps, body) — with no raw JSON blob anywhere in the dialog
- empty or null fields render as an em-dash placeholder or are omitted;
  the strings `undefined` and `null` never appear in the dialog
- single-value fields (title, description, problem/feature, solution needed,
  source, SDLC gate, lifecycle, fix version, assignee, reporter, priority,
  start date, due date) are editable in the dialog; saving posts to
  `/update`, which routes through the engine's `record_update` so every
  existing validation still applies (invalid priority, unknown or inactive
  person, malformed date are rejected and the error is shown in the dialog)
- after a successful save the dialog re-renders from a fresh `/record` read
- a comment composer adds comments through `/comment/add` with an author
  chosen from a dropdown of active project people served by `/people`
- each comment offers Edit (posts `/comment/update`) and Delete (posts
  `/comment/remove`) controls that re-render the comment list on success
- a new engine method `comment_remove` deletes one comment by id, dies
  clearly on an unknown id, updates the record's `last_updated`, and is
  exposed as `tira.comment.remove --ref REF --comment ID`
- all new routes decode strict UTF-8 payloads and round-trip `£` and emoji
  in titles and comment bodies without warnings or corruption
- `SKILLS.md` documents `tira.comment.remove` and the browser dialog
  behavior without ever mentioning the project-location argument or
  environment variable
- Docker tests pass; statement and subroutine coverage is `100%`;
  taint/perlsec and entrypoint checks pass; `cover_db` is cleaned
- Playwright proves: the sectioned render (no JSON blob), a field edit
  posting the right `/update` payload, comment add/update/remove posting the
  right payloads, and the author dropdown fed by `/people`
- `README.md`, `docs/`, `Changes`, `VERSION`, and ticket records are updated;
  release commit and push complete from the `tira` repository
