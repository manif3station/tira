# DD-497

## Title

Attachments on a question, and on its answer.

## Source

Owner voice message 3240. He asked whether I had any questions before
building, so the open one below is with him.

## What he asked for

1. **Both sides can attach.** The agent attaches files when it asks;
   the owner attaches files when he answers.
2. **Managed through the existing attachment model**, not a new one.
3. **Listing is scoped to a question.** Asking about question 1 shows
   question 1's files. Asking about question 2 shows none of question
   1's. Asking about the card without naming a question shows neither.
4. **References, not contents.** You see what is there and fetch it
   deliberately, by download or by printing it.
5. **An answer's attachments join the question's list.** The agent asks
   with two, the owner answers with one, the agent then lists that
   question and sees three.
6. **Drag and drop** to upload on the dashboard.
7. **Every attachment keeps its filename**, grouped as the attachment
   section already groups them.
8. **The answer box grows with what is typed**, rather than staying a
   fixed three rows.

## Settled by the owner (message 3243)

He resolved it the other way from his first message, and in favour of
what already shipped:

- **No question named → list everything on the card**, with names.
- **A question named → only that question's**, and several may be
  named.
- **Download by reference alone.** No card, no question, no choosing:
  the reference is enough to fetch the file.

So `DD-493` stands, and this adds a filter rather than a restriction.
The transcription of this message was poor, so my reading is stated
back to him in full; if I have it wrong he will say so before it costs
anything.

## The conflict, as it stood before he settled it

Point 3 contradicts `DD-493`, which shipped an hour before this
message. Another agent reported that `attachment.list` returned zero
for a card whose files hung off comments, read that zero as failure,
and lost time to it. I made the card's list include everything —
comments and question voice notes — precisely so a zero could be
trusted.

He is now saying the opposite for questions: the card's list should not
show them.

Both positions are defensible. Scoped listing keeps a question's
evidence with the question; the inclusive count stops a zero lying. The
resolution is probably that the **count** tells you files exist while
the **list** stays scoped, but that is my guess and it is exactly the
kind of guess that produces a tool nobody trusts.

**Asked, not assumed.** See the question put to him.
