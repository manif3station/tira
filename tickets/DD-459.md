# DD-459

## Title

Per-column staleness limits and the watched flag.

## Method

Engine TDD + CLI ATDD, red-first (`t/45-column-watch.t`).

## Problem

EPIC-457's second piece. `tira.stale` can say how long every card has
sat, but not which of those cards actually matter. The owner's decision:
each column carries its own limit, falling back to a project-wide
default, and each column can be switched out of watching entirely —
because a hundred-card backlog would otherwise fill every report and
train him to ignore it, while a finished column would nag forever about
work that is done.

## Design

- Both settings live on the column's existing entry in the board config,
  which already records name, label, order and protection. The owner
  first assumed each column folder had its own config file; it does not,
  and adding one would be a second place to keep in step.
- `notify_after` is minutes, optional per column. Absent means "use the
  project default", which lives on the project config and is asked once
  at onboarding. Absent in both means the column has no limit and its
  cards are never stale.
- `watched` defaults to true — a new column is watched unless it is
  turned off, so nothing needs configuring for the feature to work, and
  the owner switches off the columns he does not care about.
- `tira.stale` gains `--stale`, which applies each column's own limit
  rather than one number for the whole board, skips unwatched columns
  entirely, and still never returns a card whose entry was never
  recorded. `--older-than` keeps its meaning as an explicit override.
- Both are set through one command, `tira.column.update`, so the browser
  eye control and the column editor later drive the same validated path
  the CLI does — no second way to change the same setting.

## Acceptance

- per-column limit and watched flag persist on the board config and are
  reported by `column.list`
- a column with no limit falls back to the project default; with neither
  it is never stale
- unwatched columns never appear in a stale result, whatever their age
- `--stale` uses per-column limits; `--older-than` overrides with one
  number; unmeasured cards never appear under either
- invalid values exit 2 and change nothing
- Docker tests pass; coverage `100.0%`; taint gate passes; `cover_db`
  cleaned
- `SKILLS.md`, `docs/`, `Changes`, `VERSION 0.66`, tickets, BACKLOG,
  commit, and push complete
