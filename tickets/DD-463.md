# DD-463

## Title

The collector that actually nags.

## Epic

EPIC-457 — stale-card reminders.

## Owner decision this implements

Settled point 1: the collector does the sending. It scans, builds one
list, and sends a single message to the coding agent's session. Because
a Developer Dashboard collector is itself a command, the `claude`
invocation lives **there**, so Tira's own code still spawns nothing and
the documented guarantee in `docs/foundation.md` — "Tira invokes no
shell or external process" — stands unbroken.

Settled point 18: with no coding agent installed the collector stops
rather than burning resources retrying.

Settled point 19: a mid-flight failure retries once, then writes a
warning instead of failing silently.

## What the research changed

Reading the live Developer Dashboard runtime rather than the stale
workspace copy corrected three assumptions that would each have cost a
rebuild:

1. **A collector does not have to be baked into the skill.** The
   authority merges a `collectors` array from the user's own
   `~/.developer-dashboard/config/config.json`, and that is how the
   Telegram bridges on this machine already run. So a per-project
   reminder job is registered as a user-config entry, not by editing an
   installed skill — which would in any case be destroyed on the next
   reinstall.
2. **The command timeout defaults to 30 seconds and a timed-out command
   is not killed.** A coding agent will routinely take longer than
   that, so the entry sets its own timeout, and the reminder is sent
   with one attempt at a time rather than left to pile up orphans.
3. **Interval is in seconds, with a hidden 30-second floor** for
   commands starting `dashboard`. The heartbeat is in minutes, so it is
   never near the floor.

## Design

- `collector_entry` builds the Developer Dashboard entry from what the
  project stores. Pure: it computes a structure and spawns nothing, so
  it is fully covered by the suite like everything else in `lib/`.
- `collector_install` and `collector_remove` merge that entry by name
  into the user's config, never clobbering the file and never touching
  an entry belonging to something else. The name is `tira.<collector>`,
  namespaced so two projects cannot collide.
- The sending itself lives in `collector/tira-remind`, outside `lib/`
  and outside the command surface. It exits 0 and does nothing when
  there is nothing stale, when no agent is installed, or when no
  session is configured — a silent no-op rather than an error, so it
  neither lights up an error indicator nor feeds the watchdog.
- Which agent binary it runs is injectable, so the delivery path is
  proven against a stub rather than left untested until it matters.

## Acceptance criteria

1. The entry carries the namespaced name, the command, the project
   directory, the heartbeat in seconds, a timeout longer than the
   default, and singleton mode.
2. A project with no heartbeat produces no entry: no heartbeat, no
   collector.
3. Installing merges into an existing config without disturbing other
   entries; installing twice is idempotent.
4. Installing refuses to overwrite a different owner's entry of the
   same name.
5. Removing takes out only its own entry.
6. The reminder script sends nothing when nothing is stale, when no
   agent is installed, and when no session is stored, exiting 0 each
   time.
7. On a successful send, every card is recorded at its column.
8. On a failure it retries once, and after that writes a warning
   naming what failed.
