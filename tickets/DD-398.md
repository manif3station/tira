## Problem-solving evidence

1. **Repeated fields:** installed 0.09 retained only the final repeated
   `--field`: search found only `atdd.0`, and replace changed only `atdd`.
   The scalar CLI option overwrote earlier values and the engine accepted one
   field. After changing both boundaries to ordered arrays, the same search
   returned `description` then `atdd.0`; replace previewed and changed
   `description`, `bdd`, and `atdd`, while a matching comment stayed unchanged.
2. **Stable search shape:** installed 0.09 returned an array when unscoped and
   `{hits,count}` when scoped. The unscoped engine branch returned the record
   list directly. Both repetitions now return `{hits,count}`.
3. **Permanent checklist entries:** the attempted checklist-remove command was
   already rejected, and the implementation had no removal route. The gap was
   instructional: the manual now says entries are retained, not deleted, and
   to word each entry as though it will outlive the work.
4. **Import preview detail:** the pre-fix dry run already returned `dry_run=1`,
   `changed_records=1`, and one `{ref,field,before,after}` diff per changed
   field. The same workflow still passes; a concrete verified response is now
   documented rather than changing correct behavior.
