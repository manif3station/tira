# DD-388: Establish The Governed Tira Foundation And Project Lifecycle

## Method

TDD + BDD + ATDD.

## Scope

Establish the repository contract, canonical schemas, project discovery,
project creation, SOW/epic/ticket creation, immutable reference allocation, the
protected Backlog and Discard columns, the `tira.skills` documentation command,
and the TOON/JSON/Markdown output boundary.

## Acceptance criteria

- The repository contains every workspace-required governance, documentation,
  version, license, and test artifact.
- The detailed product contract agreed with the user is captured in
  `SKILLS.md` before its behavior is implemented.
- `SKILLS.md` contains a technical command catalogue with option combinations,
  invariants, failure semantics, and exactly 100 numbered use cases; command
  availability is explicit so agents cannot mistake specified behavior for a
  shipped command.
- The nested DD command layout is proven against Developer Dashboard's real
  dispatcher contract.
- Project and entity creation behavior is defined by root-level executable
  tests before implementation.
- Concurrent reference allocation cannot produce duplicate or decreasing IDs.
- All output modes and error exit codes are covered by executable tests.
- Record commands support private project-context selection without exposing
  its mechanism in the agent contract.
- Docker verification reaches 100% statement and subroutine coverage.
- After the functional and coverage gates, the implementation is audited
  against `perlsec`; taint handling, user-controlled paths, environment use,
  file operations, process execution, Unicode handling, and complexity limits
  are verified and the result is recorded.
- README, docs, Changes, ticket evidence, commit, and push complete.
